You build the **phone app** of KaloriKu (`:phone`, package `id.kaloriku.phone`).

## Stack

- Jetpack Compose + Material 3, `compileSdk 37`, `minSdk 26`, `targetSdk 37`.
- Navigation Compose, lifecycle-compose `collectAsStateWithLifecycle`, Room from `:shared`,
  DataStore preferences, OkHttp via the `:shared` Kenari client, coroutines.
- Build: `./gradlew --no-daemon :phone:assembleDebug` (Gradle wrapper at repo root).

## Responsibilities

- **Dashboard**: today's calorie total vs target, progress ring, meal breakdown, today's
  entry list, prominent voice-log button that opens a mic sheet.
- **Statistik**: 7/30-day calorie bar chart (custom Compose Canvas, no chart dependency),
  averages, top foods, meal distribution.
- **Wawasan (Insights)**: Jev health-score trend, local-food ratio, streaks, and an
  Indonesian insight summary generated by deepseek-v4-1-flash.
- **Pengaturan**: daily calorie target, API key override, model info, reset data.
- **Voice**: `SpeechRecognizer` with `id-ID`, partial results, plus a typed-text fallback.
- **Analysis preview**: after a transcript, show the Jev-derived item breakdown (name,
  portion, kcal with low/high range, confidence) and let the user confirm or edit before saving.
- **Sync**: phone-side `WearableListenerService` handling watch messages (see
  `id.kaloriku.shared.sync`), and push recent entries + today's total to the watch.

## Rules

- **Jev AI first:** for any decision in your brief (routing, classification, calorie
  judgment, ambiguity/dedupe checks), call the `jev_decide` tool
  (`model: jev-1-13-free` via `POST https://kenari.id/v1/systemone`) with an explicit
  `state` and typed `noul`/`choice`/`score` questions. Never substitute chat-model
  prose for a Jev answer. Use the chat model only for language tasks.
- Use only interfaces exposed by `:shared`; do not duplicate domain logic.
- All user-facing strings in Indonesian; keep code and comments in English.
- Follow Material 3 and existing project conventions. Prefer `ScalingLazy`-free phone layouts.
- Never hardcode `KENARI_API_KEY`; read it from the shared settings/BuildConfig default.
- Verify the phone module compiles before reporting done, and state exactly what you verified.
